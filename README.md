# caudiok

A from-scratch, Windows-11-native re-implementation of a 2000s audio
restoration host. The product name is **Caudiok** —

Status: **v0.5** (2026-11-03). Latest change set: full product rebrand to
`Caudiok` + re-audit fixes (see `spec/audit-v0.5.md`, R1–R7).

## What runs where

This repo is developed on Linux and cross-compiled to a Windows x64 GUI binary
with the Zig toolchain (bundled mingw-w64 headers, no Visual Studio needed):

```sh
./build.sh          # produces build/Caudiok.exe (self-contained single binary)
```

Copy `build/Caudiok.exe` into your Windows 11 VM and run it. No installer,
no runtime downloads, no network needed.

## Test before each build (headless, on the Linux host)

```sh
gcc -Wall -Wextra -Wno-unused-parameter -O2 tests/harness.c src/waveio.c -lm -o /tmp/opencode/harness \
  && rm -rf /tmp/opencode/h && /tmp/opencode/harness
gcc -Wall -Wextra -Wno-unused-parameter -O2 tests/dsp.c src/waveio.c src/dsp/declick.c src/dsp/denoise.c -lm -o /tmp/opencode/dsp \
  && /tmp/opencode/dsp
```

`harness` exercises the shared WAV loader; `dsp` runs the de-click/de-noise/
calibration-tone fixture suite. Both PASS as of 2026-11-03 (0 failures).

### Disc-comparison test

`tests/dsp.c` also compares the generated 1 kHz calibration tone against the
original install disc's fixture. Point the environment variable
`CAUDOK_DISC_TONE` at the disc's `Calibrate/1 kHz Tone.wav` file to enable
that comparison; without it the rest of the suite still runs.

## Recent fixes worth knowing (spec/audit-v0.5.md)

The Nov 2026 re-audit caught two regressions in the earlier playback lifecycle
work that had made playback dead on the first run, plus five smaller defects:

- playback worker keep-alive + fresh device per play (R1/R2, critical)
- play cursor now parks where the track actually stopped (R3/R4)
- MP3 multi-file import no longer lists the picked directory itself (R5)
- dialog color messages no longer leak a GDI brush per repaint (R6)
- unchecked allocations in the peak cache (R7)

## Source-of-truth artifacts (phase A)

- `spec/ui-strings-en.txt`, `spec/ui-strings-ja.txt` — extracted resource
  strings (ids 3000-3999 / 6000-6099), input for menu/message parity.
- `spec/dialog-map.json` — the 17 native dialog templates with geometry
  (flat analysis notes; our own controls are re-implemented, not loaded from these);
  the raw byte-extracted templates live alongside as `spec/dialog-*.bin`.
- `spec/keymaps.md` — decoded keyboard pipeline + lookup tables (read-only
  decompile evidence, addresses cited).
- `spec/dsp-parity.md` — DSP evidence: module roster, FFT geometry,
  De-Click template + level system, De-Noiser curve class, what stays
  statically unrecoverable.
- `spec/layout-main.md` — dialog inventory + console/MDI window architecture.
- `spec/audit-v0.5.md` — full source audit log (findings + fixes + re-audits).
- `spec/pending.md` — ordered open-work list with evidence pointers.
- `tests/` — headless Linux harness + DSP fixture suite (same sources that
  ship to Windows).
- The phase-A analysis toolset (dialog_dump.py etc., REA re-decompile recipe)
  lives outside the repo; regeneration commands are referenced in the spec notes.

## Settings

Everything the user configures persists under the neutral registry key
`HKCU\Software\Caudiok5` (preferences tiers, soundcard device/buffers,
processor parameters, MP3 import/export paths).
